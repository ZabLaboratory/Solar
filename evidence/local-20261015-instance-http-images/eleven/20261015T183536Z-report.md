# Qualification initiale — images HTTP dans les instances Solar

Ce rapport conserve le premier run de 18:35 (Chrome `154.0.8037.98`). Il précède
le test de course aux leases tardives ajouté ensuite. La qualification finale
après cette correction est consignée dans
[`20261015T184723Z-report.md`](20261015T184723Z-report.md) et correspond au run
de 18:44 dans Chrome `155.0.8059.41`.

## Résultat

Le paquet enfant LSML exact conservait auparavant ses URL d'image HTTP(S) sans
les faire passer par le résolveur d'images actif de Solar. Le changement prépare
un clone runtime de chaque source enfant, localise ses `src`/valeurs d'image via
`NativeSceneAssets`, met à jour les versions des paquets runtime et laisse les
octets, versions et pins de la source publiée intacts. Les `bindParams` d'image
rejoignent les bindings du parent ; les mutations réutilisent le résolveur, les
budgets et les leases existants. Aucun cache ou protocole parallèle n'est ajouté.

Le résolveur applique la politique `allowedHosts` du document propriétaire : les
URL écrites dans un enfant utilisent la politique de cet enfant, et une URL fournie
par un paramètre du parent utilise celle du parent. Les paquets package/assets
séparés issus de Canvas restent soumis à leurs pins SHA-256 existants.

## Limites

La preuve navigateur utilise un serveur image synthétique privé en loopback. Elle
qualifie le vrai chemin Solar/presenter/WASM/WebGL, mais pas le service ZabCanvas,
Prism en installation, la composition de capture, l'éditeur, l'admission runtime
partagée ni la sortie publique. Les contrôles cache/budgets/aborts de `NativeSceneAssets`
restent couverts par leurs suites unitaires existantes ; cette preuve n'est pas une
mesure de mémoire GPU ou de RSS. Le projet conserve aussi la distinction du contrat
actuel entre les fichiers package/assets séparés à hash SHA-256 et les URL d'image
HTTP(S) présentes dans LSML.
