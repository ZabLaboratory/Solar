# Qualification finale — images HTTP(S) dans les instances Solar

Le chemin actif acquiert maintenant les sources enfants exactes, résout les images
HTTP(S)/data-image des enfants via le `NativeSceneAssets` déjà propriétaire des
images de la scène, puis remet à Vision des copies runtime avec versions recalculées.
Les sources root/enfant, leurs versions épinglées et leurs octets restent inchangés.
Les `bindParams` de type image sont projetés sur des bindings privés du parent ; les
mutations suivantes réutilisent le résolveur, ses budgets et ses leases existants.
Les URL enfant appliquent la politique `allowedHosts` de cet enfant ; les valeurs
fournies par le parent appliquent celle du parent. Les fichiers package/assets
séparés de Canvas conservent leurs chemins SHA-256 vérifiés.

## Erreur parallèle et contrats

Une revue a trouvé un cas où une image enfant échouait pendant qu'une image d'un
enfant frère restait en attente : le rejet de `Promise.all` pouvait libérer les
leases connues avant que l'enfant lent n'en acquière un. Le nouveau test déterministe
reproduit d'abord cet échec; il passe avec `waitForAll`, qui attend l'établissement
de tous les enfants et images avant de propager la première erreur et de libérer les
leases. Le test vérifie qu'une lease arrivée tardivement est libérée exactement une
fois. Les cycles, identités et versions exactes restent contrôlés par
`acquireInstanceSources` avant la transformation runtime dans le chemin de production;
le garde `inProgress` de l'adaptateur évite aussi une récursion circulaire sur un
appel direct.

## Contrôles et limites

- Suites ciblées : 4 fichiers, 82 tests passés.
- `npm run typecheck`, `npm run lint -- --no-warn-ignored`,
  `npm run check:architecture`, `npm run build`, validation des pins Vision,
  `node --check scripts/qualify-instance-runtime.mjs` et `git diff --check` passés.
- La preuve qualifie Solar/presenter/WASM/WebGL avec des réponses synthétiques
  loopback; elle ne qualifie pas le service ZabCanvas, l'installation Prism, la
  composition de capture, l'admission runtime partagée ni la sortie publique.
  Aucune métrique mémoire GPU ou RSS fiable n'a été recueillie. Les limites du
  résolveur et la récupération GPU restent vérifiées séparément par leurs suites
  existantes; aucun profil mémoire n'est revendiqué.
