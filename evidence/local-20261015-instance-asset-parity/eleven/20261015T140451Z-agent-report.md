# AGENT_REPORT — instance asset parity

## Result

Solar now supports exact local instance package parity for safe named and SHA-1 asset paths when those files arrive inside the verified, pinned LSMLZ package already held by the local library. Explicit child requests use plain LSML and the exact scene id/version. Root and default library requests keep their LSMLZ contract. Separately fetched HTTP child assets remain constrained to the current ZabCanvas descriptor form assets/<sha256>.<ext>, with response identity headers and content digests verified.

The implementation did not add permissive named/SHA-1 HTTP fetching, invent an identity for arbitrary file paths, retry LSMLZ on integrity/budget/abort failures, or rewrite HTTP(S) image URLs embedded in child LSML. Those URL references remain a precise, separate follow-up boundary. The Main proxy was inspected and already preserves the required identity headers and response bytes, so no Prism changes are required.

## Changes

- Extended Solar's bounded cache admission to accept Vision-compatible safe package assets, verify SHA-1 and SHA-256 paths, check all asset references, reject duplicates before extraction can overwrite, and preserve the cache's size/count protections.
- Reused the existing local library path to project a verified exact LSMLZ capsule into an LSML source with standalone files, without changing the source document bytes or scene identity.
- Kept root LSMLZ requests intact while exact instance child requests use LSML with the original id, version and abort signal.
- Tightened existing Canvas HTTP asset acquisition to require the exact scene-version and revision headers and a body-matching ETag, in addition to the SHA-256 path digest.
- Added legitimate and adversarial package, provider, and HTTP fixtures; updated the private browser proof to include a SHA-1 WOFF2 path and a safe named nested PNG asset.
- Updated the Solar source-cache and scene feature documentation to state the exact supported formats and remaining HTTP(S) image URL limitation.

## Contract qualification

Vision package admission accepts safe named package-local assets and verifies recognized flat SHA-1 and SHA-256 addresses. The current ZabCanvas HTTP delivery contract is narrower: descriptors expose SHA-256-addressed local assets, and historical SHA-1 is refused by the producer because the Canvas blob store does not provide SHA-1-addressed delivery. Solar preserves that distinction. See the contract audit in this evidence directory for exact upstream pins and source locations.
