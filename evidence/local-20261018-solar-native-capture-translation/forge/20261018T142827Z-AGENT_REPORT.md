# Solar native capture translation latency report

## Scope and method

This work measures Solar's synchronous Vision receipt → native composition
projection → composition plan clone/canonical hash path for one capture x/y
translation mutation. It uses a deterministic, off-air Vitest benchmark with
synthetic receipts containing 1, 64 or 1024 captures and surfaces. In the
end-to-end timed loop, each iteration changes the first capture's x/y affine
and advances pixel and layout projection revisions. It calls the presenter
receipt validator, the public strict projector (including its own receipt
validation), projection, and `withNativeCompositionSource` with a changed exact
state hash. Isolated phase loops vary the relevant coordinate/state hash; the
hash-only loop uses fixed canonical bytes of the same plan shape.

The run used Node 24.16.0 and Vitest 4.1.11 on 2026-10-18. Each benchmark used
250 ms measurement time, 100 ms warmup and 30 target iterations. Isolated
validation, projection, plan clone, canonicalization and SHA-256 measurements
are separate benchmark loops; their means do not sum exactly to the full path.

## Results

Means and p75 are milliseconds per operation; RME is Vitest's reported relative
margin of error.

| Capture/surface count | Receipt → projection → plan hash | p75 | RME | 60 Hz budget |
| ---: | ---: | ---: | ---: | --- |
| 1 | 0.1189 ms | 0.1273 ms | ±2.84% | below |
| 64 | 3.1828 ms | 3.4520 ms | ±3.27% | below |
| 1024 | 48.9336 ms | 50.5194 ms | ±2.79% | above, synthetic stress |

At 1024 captures, separate phase means were 0.7239 ms for initial receipt
validation, 1.4300 ms for strict projection validation plus complete projection,
13.8734 ms for plan content cloning, 24.9628 ms for canonical serialization,
and 5.0340 ms for SHA-256. Plan serialization dominates this deliberately large
stress fixture. The 1024-capture result is not representative of the measured
1–64 cases.

The single-wrapper `structuredClone` experiment did not show a reliable
improvement over the existing per-field clones, and was removed from the final
benchmark. No production optimization was retained: the normal-size runs stay
well below one 60 Hz frame, and removing the second public projector validation
would weaken a mutable receipt boundary for a small stress-only saving. The
canonicalizer remains the normative implementation. No receipt checks or
composition/hash contracts changed.

## Limits

This isolates Solar CPU work only. It does not exercise a real LSDP mutation
delivery, CEF canvas copy, physical scanout, or Prism reconciliation, and it
cannot identify the cause of a user-observed drag delay. It excludes scene
transitions and scene-switch duration. The one-capture result rules out this
measured Solar synchronous composition section as a material frame-budget cost;
it does not prove the end-to-end drag is fast.
