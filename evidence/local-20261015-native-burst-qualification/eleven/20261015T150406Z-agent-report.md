# Native LSDP sustained and burst browser qualification

## Result

The 512-transaction sustained run passed at 131.51 native transactions per second. The immediate 512-transaction burst did not pass per-transaction browser coverage: the Rust subscriber lagged, Solar emitted `SUBSCRIBER_LAGGED`, and the client logged a recoverable `BASE_MISMATCH` while resynchronizing. The final authoritative daemon state and retained-canvas OCR were correct after recovery, but that does not prove that each intermediate transaction reached Vision.

The burst missed 468 transaction IDs at the Solar browser boundary. The 44 observed receive/apply pairs had matching expected hashes, while the per-transaction coverage check correctly fails because the other 468 identities were never observed or applied by this run. The daemon's final state hash matches the producer's expected final hash; the post-resync pixels therefore prove final-state recovery only.

The presentation count is a logical covering-submission count, not an image or display-frame rate. Three retained-canvas polls yielded one distinct pixel hash and one OCR attempt in each run. The browser does not expose a display-frame identity, GPU completion, or physical scanout. Solar emits `solar:lsdp-applied` after the Vision `frame-submitted` response and retained-canvas copy, so receive-to-applied is measurable as a combined boundary; a separate application-to-submission interval is unavailable. In the burst the last observed covering submission preceded the last native ACK, so last-ACK-to-last-submission drain is unavailable; last ACK to final retained-canvas OCR was 1,145.68 ms.

The burst's `BASE_MISMATCH (recoverable)` appeared once in browser console and once in the host health snapshot. These are two raw observations of the same message, not two distinct error types. One observation occurred during the measured transaction window; there were no teardown errors. Sustained had no observed errors. The earlier Arial fixture attempt is preserved as preflight evidence: Vision did not register Arial, so it produced no valid transaction measurement. The initial browser readiness timeout is also retained as an invalid zero-transaction attempt; neither is mixed into the final measurements.
