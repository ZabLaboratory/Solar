# AGENT_REPORT — Solar GPU context recovery

## Result

The current Solar/Vision path successfully recovers from a controlled browser WebGL context loss. I found no product defect that justifies a `src/` patch, a Vision change, or a pin/WASM rebuild. Solar uses Vision's desynchronized WebGL2 main-thread presenter and does not automatically switch to the standalone WebGPU worker or the separate software renderer.

During loss, Vision retains the accepted scene state in its Rust engine. On restoration it recreates the WebGL projection, re-registers active images and submits the current accepted state. Solar's retained front canvas is replaced only after `frame-submitted`, so the last accepted image remains visible while recovery is pending. A failed recovery is emitted as `type=error, phase=context`; Solar routes an unclaimed presenter error to the host `onError` callback (or rejects its owning request waiter).
